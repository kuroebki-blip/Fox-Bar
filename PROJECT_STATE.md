# FO’X — состояние проекта

Актуально на 22 августа 2026 года.

## Архитектура

- FO’X: Telegram Mini App, опубликованная из корневого `index.html` через GitHub Pages.
- Tatooine: отдельная Mini App кассового отчёта в `tatooine/`, отдельный Telegram-бот.
- FO’X и Tatooine используют общий Apps Script обработчик сканера/кассового отчёта, но отдельные Telegram-маршруты.
- Банкетный модуль использует цепочку Mini App → Cloudinary → URL → Apps Script → Google Sheets.
- Gemini вызывается из Apps Script; ключи и токены должны находиться только в Script Properties.

Подробнее: `ARCHITECTURE.md` и документы в `docs/`.

Frontend-релиз `v15.14.3` очищает хаб, таблицы и банкетный экран от декоративных повторяющихся пояснений, а кассовый отчёт — от технической подписи; рабочие инструкции, статусы и навигация сохранены. Предыдущий релиз `v15.14.2` убирает выбор «Документ / Ч/Б» из preview сканера и скрывает промежуточные описания при активном прогрессе; финальные сообщения и ошибки сохранены.

Tatooine-релиз `v1.8.0` добавляет этап 1 развоза: домашний адрес сотрудника, явная заявка «Еду домой» на текущую дату, отмена, менеджерский список активных заявок и server-side защита адресов. Маршрутизация, координаты и интеграции такси не реализованы. RBAC-инфраструктура остаётся прежней: пользователь получает роль и permissions одним bootstrap-запросом, а первый `superadmin` задан через Script Property без его хранения в репозитории.

Tatooine `v1.8.1` добавляет менеджерский выбор адреса через Geoapify: подсказки запрашиваются только при вводе адреса, защищены `rides.manage_addresses`, а выбранный вариант сохраняет координаты. Для живой работы требуется Script Property `GEOAPIFY_API_KEY`; ключ не хранится в Git.

Tatooine `v1.8.2` добавляет настраиваемую точку начала развоза: primary Location хранит адрес и координаты, доступ к настройке ограничен `rides.manage_origin` для admin/superadmin, а изменения записываются в отдельный audit-лист. Живой Telegram-тест настройки адреса остаётся отдельным пунктом.

- Живой тест банкетов и формул Google Sheets после текущего frontend-релиза не подтверждён.

## Известные проблемы

- Терминальные чеки могли распознавать произвольные неверные цифры; пользователь подтвердил сильное ухудшение Tatooine на входном монтаже 2×2.
- Несколько банкетов на одну дату, снятие резерва после завершения и добавление новых позиций требуют проверки на фактическом production backend.
- Скорость сканера документов на реальном Android требует замера.
- Актуальные идентификаторы таблиц и значения Script Properties неизвестны репозиторию.
