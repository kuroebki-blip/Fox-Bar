# Безопасность FO’X

## Никогда не коммитить

- Gemini API Key и другие API-ключи.
- Telegram Bot Token.
- Cloudinary API Secret.
- Пароли, приватные ключи, session cookies.
- `.env`, дампы окружения и экспорт Script Properties.
- Содержимое рабочих Google Sheets.

Секреты Apps Script должны храниться только в Script Properties. Во frontend допустимы публичные Web App URL, Cloudinary cloud name и unsigned upload preset.

## Проверка перед коммитом

Сначала проверить только пути изменённых файлов:

```sh
git diff --cached --name-only
```

Искать возможные значения только в режиме вывода имён файлов:

```sh
rg -l --hidden -g '!*.zip' 'AIza[0-9A-Za-z_-]{30,}|[0-9]{8,10}:[0-9A-Za-z_-]{30,}|-----BEGIN (RSA |EC |OPENSSH )?PRIVATE KEY-----|cloudinary://[^[:space:]]+' .
```

Для проверки истории без вывода содержимого:

```sh
pattern='AIza[0-9A-Za-z_-]{30,}|[0-9]{8,10}:[0-9A-Za-z_-]{30,}|-----BEGIN (RSA |EC |OPENSSH )?PRIVATE KEY-----|cloudinary://[^[:space:]]+'
git rev-list --all | while read -r revision; do git grep -Il -E "$pattern" "$revision" -- ':!*.zip' || true; done | sort -u
```

Команды выводят только путь либо `commit:path`, а не найденное значение. Совпадение имени переменной само по себе не является утечкой. Проверяющий сообщает только путь, тип риска и рекомендуемую ротацию — найденное значение целиком не копируется в issue, PR или чат.

Если обнаружен реальный секрет:

1. Не публиковать commit.
2. Немедленно отозвать или ротировать секрет у провайдера.
3. Удалить значение из рабочей копии и истории согласованным способом.
4. Проверить логи доступа.
5. Зафиксировать инцидент без раскрытия значения.

## Текущее состояние

Документационный Developer Kit не содержит значений секретов. Финальная проверка всей ветки обязательна перед Pull Request.
