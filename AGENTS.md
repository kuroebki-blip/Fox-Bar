# FO’X — правила работы с репозиторием

Этот файл обязателен к прочтению перед изменениями.

## Порядок работы

1. Сначала определить затронутый компонент и изучить связанные исходники, историю и документацию.
2. Провести диагностику, затем предложить минимальную правку.
3. Не переписывать рабочую систему вслепую.
4. Frontend и backend менять только тогда, когда это необходимо для задачи.
5. До правки назвать точные файлы; после правки показать diff, тесты, риски и план отката.
6. Не объявлять функцию рабочей без автоматического теста или подтверждения пользователя.
7. Работать в отдельной ветке. Один релиз — одна версия и запись в `CHANGELOG.md`.

## Компоненты с повышенным риском

- Не запускать `setupBanquetsBackend()` и другие setup-функции без прямого подтверждения пользователя.
- Не менять backend банкетов для задачи, ограниченной frontend.
- Не удалять формулы, значения или стили Google Sheets.
- Перед изменением таблицы всегда создавать новую версию или копию.
- Не сдвигать колонки и не переименовывать листы без синхронного обновления интеграций и тестов.
- Фото банкетов идут напрямую в Cloudinary; не возвращать передачу фото через Apps Script/base64.
- Фото документов и кассовых отчётов не должны сохраняться в Google Sheets.

## Секреты

Не хранить в Git API-ключи, Telegram Bot Token, Cloudinary API Secret, пароли, приватные ключи, `.env` и экспорт Script Properties. Допустимы только заведомо публичные Web App URL, Cloudinary cloud name и unsigned preset. Перед коммитом выполнить проверку по `SECURITY.md`.

## Документация

- `AGENTS.md` обновлять только при изменении архитектуры, постоянных правил, состава модулей или процесса разработки.
- `PROJECT_STATE.md` обновлять после подтверждённого релиза.
- `CHANGELOG.md` обновлять при каждом версионированном изменении.
- `ROADMAP.md` обновлять при изменении планов и приоритетов.
- Обычные мелкие исправления не добавлять в `AGENTS.md`.

## Проверка релиза

Использовать `RELEASE_CHECKLIST.md` и профильный раздел `TESTING_CHECKLIST.md`. Обязательно указать версию, проверенные сценарии, непроверенные сценарии, риски и точный способ отката.
