# Сток

## Базовая структура

| Колонка | Значение |
| --- | --- |
| A | Наименование |
| B | ЗАКАЗ |
| C | Сток |
| D | Остаток Аллея |
| E | Остаток Заготовочный |
| F | Цена |
| G | Сумма остатка |
| H | Ед. изм. |
| I | Примечание |
| J | Банкеты |

Для версии с банкетным резервом базовые формулы:

- `G = D + E`
- `B = MAX(0, C - G + J)`

## Ограничения

- Не удалять формулы, значения и стили.
- До массовой правки создавать новую версию или копию таблицы.
- Не сдвигать колонки и не переименовывать листы без обновления Apps Script и тестов.
- Не выполнять setup-функции без прямого разрешения.

Фактическая production-структура Google Sheets не хранится в Git и требует подтверждения пользователя.

## Candidate v16.0.0: банкетный резерв

Изменения в `feature/v16-banquets-upgrade` не изменяют формулы B/G/J и не создают листы или колонки.

- Перед сохранением OCR-резерва Stock backend читает текущий статус банкета напрямую из листа `Банкеты`; статус, присланный frontend, не является источником истины.
- `Выполнено` и `Отменено` сохраняются в резерве даже при позднем завершении OCR, поэтому J учитывает только строки `Актуально`.
- Неизвестные товары сохраняются в `Банкеты_Резерв` с исходным названием, количеством, единицей и статусом `Требует сопоставления`. Они не попадают в J до ручного сопоставления.
- Операции записи резерва используют `LockService.getDocumentLock()`. Это сериализует изменения внутри Stock/Reserve Apps Script; два отдельных Apps Script-проекта не имеют одного общего LockService-lock.
