# FO’X — changelog

История основана на коммитах публичного репозитория. Неподтверждённые backend-изменения не считаются production.

## Unreleased

### Added

- Candidate FO’X calendar: раздел банкетов переименован в «Календарь». Сотрудник видит свои смены и обведённые рабочие дни, а при выборе даты — состав работающего персонала. В завершённом банкете admin/superadmin может сохранить итоговую сумму числом для будущей аналитики.
- Candidate FO’X schedules: администратор загружает изображение рабочего графика напрямую в Cloudinary; Gemini по URL возвращает редактируемый черновик смен. После подтверждения активный график хранится по месяцу, а в карточке банкета лениво отображаются сотрудники с рабочей сменой на его дату.
- Tatooine `v1.10.0`: развоз привязан к операционной смене 14:00→13:59 в timezone Apps Script. Заявки, Matrix и Optimization используют единый shift key; remove/self-cancel немедленно инвалидируют состав маршрута в менеджерском UI.
- Tatooine `v1.9.4` experiment: карточки сформированных машин временно могут открыть их уже рассчитанный порядок точек в Яндекс Картах или скопировать весь маршрут одной строкой. Optimizer и Matrix не меняются.
- Tatooine `v1.9.5`: кнопка машины запускает документированную нативную URL-схему Яндекс Карт через Telegram `openLink`, поэтому Mini App не заменяется страницей `maps.yandex.ru`; URL строится из сохранённых координат и `dropoffOrder`.
- Tatooine `v1.9.6`: нативная схема Яндекс Карт запускается прямой ссылкой с `target="_blank"` из пользовательского клика, а не через Telegram bridge, который не передавал custom scheme в iOS.
- Tatooine `v1.9.7`: после фактической ошибки `WebAppTgUrlInvalid` custom scheme исключена. Кнопка передаёт официальный HTTPS URL маршрута в Telegram `openLink`, который открывается внешне и не заменяет экран Mini App.

### Fixed

- FO’X `v15.14.6`: месяц графика задаётся администратором и передаётся в Gemini OCR как источник истины. Отсутствующий месяц на изображении больше не прерывает распознавание.
- FO’X `v15.14.5`: распознавание изображения графика показывает отдельный прогресс и понятную ошибку прямо в форме; ожидание Gemini OCR увеличено до 90 секунд вместо общего JSONP-лимита 15 секунд.
- Candidate FO’X schedules: загрузка графика вынесена в отдельную кнопку «График сотрудников» в разделе банкетов; форма OCR не занимает экран до явного открытия.
- Candidate `v16.0.0` Banquets: банкетный резерв теперь сверяется с актуальными статусами исходной таблицы банкетов при каждой загрузке сводки. Завершённые и отменённые банкеты немедленно исключаются из резерва, удалённые архивируются, а зависшие исторические строки очищаются автоматически.
- Tatooine performance: обычное открытие сохранённых машин больше не загружает Route Details и всю directed matrix; данные маршрута загружаются только для явного открытия/копирования маршрута. Backend читает строки участников и edges выбранного calculation через целевой range, а не переносит всю историю листов в execution.
- Tatooine `v1.10.7`: `config.js` стал единым источником отображаемой версии и обновлён с `v1.10.6`; он также загружается с версионным параметром, поэтому плашка не может быть перезаписана старым закешированным config.
- Tatooine `v1.10.8`: добавлен отдельный release path с самостоятельной HTML-страницей для запуска из Telegram. Он исключает повторное использование Mini App HTML, который Telegram кеширует по прежнему пути; функциональность приложения и backend не изменяются.
- Tatooine `v1.10.7`: frontend подключает `app.js` с версионным параметром, чтобы Telegram Mini App не оставался на закэшированной v1.10.6 после публикации.
- Tatooine `v1.10.7`: «Сформировать машины» теперь использует подтверждённый JSONP-ответ Apps Script вместо opaque `no-cors` POST. Ошибка backend или отсутствие ответа за 45 секунд завершают loading-state и разблокируют кнопку; результат оптимизации возвращается сразу после сохранения.
- Tatooine `v1.10.3`: действия «Еду домой» и «Убрать из развоза» больше не отправляются opaque `no-cors` POST. Они получают подтверждённый или отклонённый ответ Apps Script через уже используемый авторизованный JSONP-канал.
- Tatooine `v1.10.2`: подтверждение записи развоза больше не перерисовывает менеджерский список на каждой проверке. Повторные клики по действию блокируются до завершения, а пользователю показывается единый статус «Сохраняю…».
- Tatooine `v1.10.1`: сохранение заявок развоза теперь подтверждается polling-ом фактического состояния вместо единственной проверки через 300 мс после `no-cors` Apps Script POST. Это исключает ложную ошибку и неработающее удаление при обычной задержке Apps Script.
- Tatooine `v1.9.3`: сохранённый Route Matrix и результат оптимизации нормализуют дату Google Sheets при чтении, поэтому готовый расчёт корректно возвращается в приложение после polling.
- Tatooine `v1.9.2`: старые повторные заявки на развоз по одному сотруднику и дню перестали попадать в активный список и Route Matrix; при очистке сохраняется последняя по времени заявка.
- Tatooine `v1.9.1`: дата заявки развоза, возвращаемая Google Sheets как Date, нормализуется до `YYYY-MM-DD`. Активные заявки снова отображаются в тот же день, а повторное подтверждение обновляет существующую запись вместо создания дубликата.

### Changed

- Candidate Tatooine `v1.9.0`: добавлен явный расчёт полной дорожной матрицы Geoapify для точки старта и активных заявок развоза. Результат, snapshots и directed edges сохраняются отдельно, доступны только по `rides.optimize`; optimizer, машины и заказ такси не добавлены.
- Tatooine `v1.8.3`: при открытии «Такси» независимые запросы своего статуса, списка развоза и адресов сотрудников выполняются параллельно. Это устраняет последовательный Apps Script waterfall для manager/admin без изменения состава данных или прав доступа.
- Tatooine `v1.8.2`: добавлена настраиваемая точка начала развоза. Её адрес и координаты хранятся в отдельной Location-записи, а изменение доступно только по permission `rides.manage_origin` (admin/superadmin), проверяемому также на backend.
- Tatooine `v1.8.1`: менеджерский ввод домашнего адреса развоза получил подсказки Geoapify с исправлением опечаток и сохранением координат выбранного варианта. Запросы выполняются лениво и только для `rides.manage_addresses`; ключ остаётся в Script Properties.
- Tatooine `v1.8.0`: добавлен этап 1 развоза сотрудников — постоянный домашний адрес, явная заявка «Еду домой» на текущую дату, отмена, ленивый менеджерский список активных заявок и server-side защита адресов. Маршрутизация, координаты, машины и интеграции такси не входят в релиз.
- Tatooine `v1.7.1`: кассовый отчёт, такси и управление ролями вынесены в отдельные пункты хаба. Управление ролями отображается только `superadmin` и загружает список сотрудников только при открытии раздела; экран такси пока является навигационной заглушкой до подключения самого модуля развоза.
- Tatooine `v1.7.0`: добавлена RBAC-основа на базе проверенного Telegram ID: роли `employee`, `manager`, `admin`, `superadmin`, единая permission matrix, server-side проверки ролей, безопасный bootstrap первого superadmin, журнал смены ролей и компактный экран управления доступом.
- FO’X `v15.14.4`: в кассовом отчёте удалены «Нал2» (Наличные 2) и Tapper; добавлено поле `EatAndSplit`, автоматически заполняемое из распознанных строк оплат `EatAndSplit` или `Items Split`. Строка отчёта продолжает использовать существующий зелёный Telegram custom emoji-маркер FO’X.
- Tatooine `v1.6.0`: кассовый OCR приведён к pipeline FO’X — цельный JPEG до 2200 px с качеством `.84`; перед добавлением фото доступен on-demand preview scanner с автообрезкой, выравниванием и выбором оригинала. OpenCV не прогревается при старте.
- FO’X `v15.14.3`: главный хаб, таблицы и банкетный экран очищены от повторяющихся декоративных пояснений; техническая подпись кассового отчёта удалена, а карточки уплотнены без изменения рабочих инструкций, статусов или навигации.
- FO’X `v15.14.2`: scanner preview больше не предлагает выбор «Документ / Ч/Б»; во время активной обработки документов, чеков и кассовых отчётов отображается только progress bar, а финальные состояния и ошибки остаются текстовыми.
- FO’X `v15.14.1`: банкетная база загружается при первом входе в раздел, OpenCV не прогревается при старте, а jsPDF загружается один раз по требованию перед созданием PDF. Это уменьшает initial startup cost без изменения формата PDF и пользовательских сценариев.

### Added

- Candidate FO’X document scanner: общий OpenCV.js pipeline с поиском границ, perspective transform, фильтрами и preview перед существующим Gemini OCR; Tatooine пока не меняется.
- Candidate `v16.0.0` Banquets Upgrade: idempotent save by banquet ID, backward-compatible `Media JSON` support, multi-photo frontend gallery and sequential OCR, preservation of unknown goods, and local regression tests.
- Developer Kit: архитектура, состояние проекта, правила разработки, безопасность, чек-листы и документация компонентов.
- Candidate Tatooine `v1.5.0`: встроенная задняя камера для Telegram WebView на Android с fallback на обычный выбор фотографии.
- Candidate Tatooine `v1.5.1`: полноразмерный Android-снимок через `ImageCapture` с сохранением canvas fallback.
- Candidate Tatooine `v1.5.2`: цельный OCR-снимок до 3200 px без монтажа 2×2.
- Candidate Tatooine `v1.5.3`: ожидание status-ответа Apps Script увеличено до 35 секунд; временная задержка сервера отображается как повторная попытка, а не как финальная ошибка.
- Candidate Tatooine `v1.5.4`: временная задержка status-ответа не меняет текст статуса; приложение продолжает опрос в фоне.

### Changed

- Candidate FO’X: кассовый OCR передаёт цельное изображение до 2200 px вместо 3200 px мозаики из четырёх фрагментов; Android-камера для кассового отчёта сохраняет более компактный кадр. Это уменьшает локальную обработку и размер отправки в Gemini.
- Candidate `v16.0.0`: Stock/Reserve backend reads the banquet status directly from the Banquets sheet before saving a reserve; terminal statuses are retained after late OCR.
- Candidate `v16.0.0`: reserve status updates report the actual number of changed rows and fail when no active reserve exists.

### Fixed

- Candidate FO’X: автообрезка документов теперь ищет контур по нескольким вариантам изображения (обычные и мягкие границы, контрастный порог); preview явно сообщает, была ли обрезка и коррекция перспективы применена.
- Candidate FO’X: на Android в Telegram съёмка документов и кассового отчёта использует совместимый поток камеры, как в Tatooine; иначе WebView предлагает только галерею. На iPhone остаётся системная камера без управления фонариком видеопотока.
- Candidate `v16.0.0`: repeated save POSTs with the same banquet ID no longer append a duplicate row.
- Candidate `v16.0.0`: unknown banquet goods are retained with quantity and unit as `Требует сопоставления` instead of being discarded before reconciliation.
- Android Telegram больше не зависит только от необязательной поддержки HTML `capture` при съёмке кассового отчёта.
- Снимок Android-камеры больше не ограничивается разрешением preview-видеопотока, если WebView поддерживает `ImageCapture`.
- Tatooine больше не переставляет и не дублирует фрагменты документа перед отправкой в OCR.
- Tatooine не показывает ложную ошибку «Сервер не ответил вовремя» при кратковременной задержке Apps Script/Gemini.
- Из Tatooine убрано сообщение о временной занятости сервера во время повторного опроса.

### Removed

- Нет.

## 2026-07-26 — frontend v15.14.0 / Tatooine v1.4.0

### Added

- Детальная монтажная OCR-страница 2×2 для каждой исходной фотографии кассового отчёта.

### Changed

- Кассовый OCR FO’X и Tatooine использует увеличенное изображение без добавления отдельных Gemini-запросов на каждый сектор.

### Fixed

- Backend-инструкция различает перекрывающиеся фрагменты одного физического терминального слипа. Исходник backend находится вне `main`; deployment требует отдельной проверки при следующем релизе.

### Removed

- Нет.

## 2026-07-22 — Tatooine v1.3.0–v1.3.3

### Added

- Финальный отчёт Tatooine на основе iiko 041.
- Поддержка EatAndSplit, Яндекс Еды, размена и предоплат.

### Changed

- Стандартный неизменный размен установлен в `100 000`.
- Блок предоплат и `Итого` показываются только при наличии предоплат.

### Fixed

- Нормализация платёжных строк iiko с префиксом `Оплата`.
- Пустые обязательные строки отчёта сохраняются в шаблоне.

### Removed

- Из Tatooine убраны лишние строки, не входящие в согласованный шаблон iiko 041.

## 2026-07-22 — Tatooine v1.0.0–v1.2.1

### Added

- Отдельное приложение Tatooine и маршрут отдельного Telegram-бота.
- Шаблон кассового отчёта Petrovka/Tatooine.

### Changed

- Формат сообщения приведён к согласованным переносам строк и выделениям.

### Fixed

- Выбранные фото сохраняются до сброса file input в Telegram WebView.

### Removed

- Нет.
- Tatooine `v1.10.4`: экран «Развоз» загружает Apps Script данные последовательно, чтобы не создавать очередь запросов в Telegram; при ошибке обновления старый список сотрудников очищается и не выдаётся за актуальный.
- Tatooine `v1.10.5`: при удалении сотрудника из развоза карточка показывает «Убираем…», затем после подтверждения backend плавно исчезает; при ошибке возвращается исходная кнопка.
- Tatooine `v1.10.6`: подтверждённая отмена развоза больше не откатывается запоздалым ответом списка; карточки менеджера дедуплицируются по сотруднику.
